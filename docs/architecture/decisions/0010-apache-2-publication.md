# 0010 — Apache 2.0 publication from a reviewed fresh history

- Status: accepted for preparation; human review and publication remain required
- Date: 2026-11-10

## Context

Portable CMS is being prepared for public contribution. Its private development
archive contains client-specific planning and historical material that must not
become part of the public repository. Internal task identifiers are permanent.
A new public history was explicitly selected on 2026-11-10; the existing repository
and its branches remain private. Publication does not authorize copying their
Git objects, merging their branches, changing visibility, or deleting claims.

## Decision

The product name at publication is **Portable CMS**. Original software,
documentation and original fictional acceptance material are offered under
**Apache License 2.0**, copyright **2026 Utsuri Foundry, SL**. The `Utsuri` PHP
vendor namespace and package identifier remain for compatibility. The licence
does not grant rights to the company's marks beyond Apache section 6.

Use Apache section 5 for intentional contributions. No DCO or separate CLA is
required. Contributors must have the right to submit their work, identify any
third-party material, and retain its licence and attribution.

Do not add SPDX headers mechanically to every file. The root LICENSE, NOTICE,
Composer metadata and third-party inventory define the grant and exceptions.
This avoids changing canonical fixtures, generated bytes and embedded script
hashes solely to add headers. Imported licences and copyright notices remain
verbatim; an Apache header must never relabel an OFL font or third-party file.
The public repository check verifies the licence and distribution materials.

Prepare the public repository from an explicit reviewed source snapshot, with
one new root commit and no borrowed object store, refs, tags, remotes, hooks or
reflogs. Keep the private archive intact. Internal task records, claim metadata,
private audit inputs and reports are excluded. Public contributors use ordinary
Git branches, issues and pull requests; no private coordination program is needed
for the repository check. Maintainers retain their internal ownership workflow
until cutover. In-flight work must be reviewed and imported as a new patch,
never merged with its private ancestry.

No written permission to identify clients is assumed. Remove identifying prose
from published documentation while retaining the technical fact. Keep necessary
historical planning, permanent task IDs and the detailed identity/branch audit in
the private archive. The public audit summary contains scope, method, counts and
disposition, not the identities or secret material it is intended to withhold.
Reference Studio remains fictional; its identity, authored content and design
are preserved.

## Third-party material

The locked runtime family is `opis/json-schema`, `opis/string` and `opis/uri`,
all Apache-2.0. Installed bundles retain their upstream licence files. The
Composer-generated autoload support is MIT-licensed, pinned by the build tool
in the Nix lock, and retains its complete vendor/composer/LICENSE in bundles.
The
Reference Studio font derivatives remain **OFL-1.1**, aggregated with the code,
not relicensed under Apache. They retain Adobe's copyright and RFN notices and
use the renamed Studio Sans / Studio Serif families. Inventory, exact versions,
licence locations and provenance are recorded in THIRD_PARTY.md and the profile's
PROVENANCE.md. Original geometric images and the icon are first-party material.
The initial inventory missed the original video recipe already recorded in
tests/README.md. Both clips are authored silent colour frames, not imported
footage. Retain their reviewed bytes, recipe, checksums and ownership statement
in tests/fixtures/video/README.md; unknown-origin media is not admitted.

Gitleaks and FFmpeg are developer-only audit/preparation tools, resolved through
the existing public Nix lock. They are not installed runtime dependencies or
third-party source copied into the product. Their licences and boundaries are
included in the development dependency review. No scanner finding is ignored
merely because it occurs in a fixture: each disposition needs evidence.

## Publication evidence and activation

Audit the tracked tree, paths, Git metadata and all reachable commits from all
fetched remote branches with Gitleaks and a private identity list. Review false
positives and media provenance. Independently scan the exported tree and its new
history. Every old branch is deliberately retained **private**, including open
claims; none is copied into the public repository.

Test a fresh clone of the candidate with a clean home/environment and no office
credentials or private tools. Record exactly where the check ran; a local isolated
clone is not evidence of execution outside the office. Prepare an external CI
workflow and GitHub settings for a reviewed private candidate. The person making
the visibility switch must verify branch protection, reporting, description and
topics. GitHub documents private vulnerability reporting for public repositories;
if it cannot be enabled while private, enabling and verifying it immediately at
cutover is an explicit human activation step, with a private reporting channel
available in SECURITY.md. Never report an unapplied setting as verified.

The publication tools prepare artifacts and evidence. They never change GitHub
visibility, rewrite the archive, delete remote branches, push, or publish without
a separately authorized operation.

## Alternatives and consequences

An in-place history rewrite was rejected: it would disrupt permanent internal
IDs and ownership, and leave greater risk of exposing old refs or cached history.
Making the existing repository public is explicitly rejected. A source snapshot
is not a licence audit by itself; the third-party and secret reviews still apply.
The new public repository will not contain the private development chronology.
The private archive retains the detailed extraction proof; public provenance
explains the origin and boundaries without naming private repositories or clients.
